## 一、项目现状盘点（已有的简历资产）

经过近期多轮迭代，项目已具备 Agent 开发岗位最看重的几块硬实力，且全部有量化数据支撑：

| 能力 | 现状 | 简历可用素材 |
|---|---|---|
| 多 Agent 编排 | 主 Agent + 分析/报告专家，隔离上下文、预算治理、依赖 deepagents/langgraph | 三角色管线、program 状态机、fast-path 路由 |
| 防幻觉架构 | 指标绑定门（数字必须来自已验证指标）、验证边界、confirmed-only 流式 | "回答含未绑定数值"类死锁的发现与修复过程 |
| 工程化任务系统 | 文件任务账本、温热常驻执行器、协作取消、watchdog、Docker 沙箱 | 冷启动 6.7s→0（简单问答 12s→5.3s，-56%） |
| 质量与稳定性 | 651 pytest + vitest 10 + e2e 10，三轮缺陷审查修复 16+ 个真实缺陷 | 中等分析 183s→43s；失败任务部分交付 |
| 前后端全栈 | React 19 + TanStack Query + SSE 流式 + antd；FastAPI + pydantic 契约 | 步骤条/分段流式/会话管理全链路 |

结论：**编排、工具调用、工程化、安全防护四块已经超出多数同类简历项目**，缺口集中在下面三块。

## 二、目标岗位画像与差距分析

对照 Agent/大模型应用开发岗的常见 JD：

| JD 高频要求 | 现状 | 差距 |
|---|---|---|
| LangChain/LangGraph/Agent 框架 | ✅ 深度实战 | 无 |
| Function Calling / 工具编排 | ✅ | 无 |
| Multi-Agent 协作 | ✅ 管线模式 | 缺动态规划/任务分解模式（可选加强） |
| **MCP（Model Context Protocol）** | ❌ | **补：把工作台能力暴露为 MCP 工具服务** |
| **RAG / 向量检索** | ❌（记忆是关键词匹配） | **补：向量化的知识库与 Agent 记忆检索** |
| **Agent 评测 / 可观测性** | ❌（有 perf span，无评估体系） | **补：golden set 回归评分 + Langfuse 追踪** |
| 部署上线 | ❌ 仅本地 | 补：Docker Compose + 鉴权 + HTTPS 云部署 |
| 多模态 / 语音 | ❌ | 可选，非必须 |

## 三、技术栈补齐（按优先级）

1. **MCP 协议（最高优先）**：用官方 Python SDK 把 DS Studio 的核心能力（提问分析、查询指标、生成报告、检索记忆）封装成 MCP Server，使其可被 Claude/Cursor 等任何 MCP 客户端调用——这是当前 Agent 岗位提及率最高的协议，且与现有项目天然契合。
2. **向量检索**：引入 sqlite-vec（零部署成本）为知识库与 Agent 记忆做语义检索，替代纯关键词匹配；简历可写"混合检索（关键词+向量）"。
3. **Agent 评测**：构建 golden set（20~30 个带标准答案的问题），写回归评分脚本（答案正确性 + 延迟 + token 成本），接 Langfuse 做调用追踪——"如何评估 Agent 质量"是面试必问题。
4. **结构化输出可靠性**：已有 metric 绑定门的实践，补上 provider 结构化输出（JSON Schema）对比与降级策略。

## 四、部署上线方案（建议做，分两级）

**级别 1（推荐执行）：单机 Docker Compose 云部署**
- 组成：`app` 容器（FastAPI + 前端静态构建）+ 常驻 worker + 沙箱镜像；可选 PostgreSQL 容器。
- **前置必须：加鉴权**（当前完全无登录，公网裸奔不可接受）——实现简单 Token/登录页 + 管理员单账号即可。
- HTTPS：Caddy 反向代理自动证书；模型代理密钥仅存服务端 `.env`。
- 演示策略：内置示例数据集的预置演示会话（访客只读），避免公开写入口。
- 成本：轻量云服务器 2C4G 约 50~100 元/月；沙箱容器已有内存/CPU 限额。
- 产出：简历上的线上 Demo 链接 + 一段真实的部署运维经验（Compose 编排、迁移、备份脚本）。

**级别 2（简历项目不建议实施，面试讲设计）**：多租户/多用户隔离、K8s、横向扩容——面试口述权衡即可，做了反而增加维护面。
