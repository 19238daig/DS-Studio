# DS Studio · React + FastAPI 前端迁移落地方案

```tldr 推荐方案
以 **React + TypeScript + Vite** 重建展示层，以 **Ant Design 定制组件 + CSS Modules** 建立成熟的数据分析产品界面；继续复用现有 FastAPI、Deep Agents、Worker、PostgreSQL、Docker 和报告服务。

交付目标是完整替代 Streamlit 的正式界面，保留所有现有业务功能与历史数据。用户确认本方案后，先建立功能对照和接口契约，再分阶段实现、验证和切换。本次只生成方案文档。
```

## 1. 当前项目核查结论

以下内容来自对本地实际代码的只读检查，而非仅根据历史架构图推测。

| 核查项 | 已确认的现状 | 对迁移的影响 |
| --- | --- | --- |
| 展示入口 | `app.py` 使用 Streamlit；`src/ui_theme.css` 等控制布局 | 重建展示层和前端状态，不将 Python 组件逐行翻译成 JSX |
| 业务访问 | `src/client.py` 已经通过 HTTP 调用 FastAPI | React 可对接已有接口，后端业务层无需整体重写 |
| 后端 | `src/api.py` 提供 `/api/v1` 会话、文件、数据库、任务、SSE、报告和记忆接口 | 保持 API 路径和现有服务行为，按需增补兼容字段与接口 |
| 实时协议 | 已有 SSE 游标、快照恢复、终态和轮询兜底机制 | 浏览器实现订阅管理；不另建 WebSocket 任务系统 |
| 报告 | 已有不可变版本、SVG、来源校验、对应回复附件 | 新界面继续绑定 `session_id + task_id + artifact_id`，不只显示最新文件 |
| 当前修改 | `app.py`、`src/api.py` 有未提交修改；API 已加入本地开发 CORS 白名单 | 实施前先保护这些修改，再以当前内容为基线整合 |
| React 目录 | `frontend/`、`web/` 只发现 `.vite` 缓存，未发现应用级 `package.json` 和可运行 React 源码 | 建议统一采用 `frontend/`，不把缓存视为已完成项目，也不直接覆盖现有目录 |
| 本机工具 | Node.js `22.21.0`、npm `10.9.4` | 满足当前 Vite 文档列出的 Node.js 22.12+ 基线；仍须在实施时核对模板实际要求 |

FastAPI 中多个接口目前直接返回字典，OpenAPI 对部分响应的描述不完整。**不能假设现有 OpenAPI 已能直接生成完整 TypeScript 业务类型。** 迁移会先补齐响应契约，再生成类型。

本方案不读取密钥内容，不携带真实数据集或聊天记录；文中的界面示意不代表已开发页面或真实分析结果。

## 2. 迁移边界与最终运行架构

[[architecture-diagram]]

| 层次 | 本次处理 | 保留的业务边界 |
| --- | --- | --- |
| React 展示层 | 新建路由、组件、交互、缓存、上传与订阅管理 | 不直接连接模型服务，不直接读主机文件或 PostgreSQL |
| FastAPI 接口层 | 复用现有接口；补响应类型、指定报告版本与安全预览入口 | 继续统一执行来源选择、任务受理、权限和产物校验 |
| Agent / Worker | 通过原有任务接口调用 | 主 Agent、两位专家、独立记忆、工具预算和任务隔离保持原服务机制 |
| 分析与报告 | 使用已登记的结果和产物 | 计算由后端完成；前端不从预览心算指标，不覆盖原报告 |
| 数据与状态 | 使用现有工作区和 PostgreSQL | 不迁移、清空或重新导入既有会话、知识库、记忆和报告目录 |

**正式版不再运行 Streamlit。** 迁移期保留旧入口用于功能对照，完成验收后从生产启动流程与生产依赖中移除 Streamlit；回滚依靠迁移前代码版本，而不是同时运行两套会话写入流程。

测试也同步迁移：Streamlit 专属 AppTest 由 React 组件交互和浏览器 E2E 场景替代；Python 业务、来源权限和报告校验测试继续保留，避免正式版为了运行旧界面测试而重新依赖 Streamlit。

React 主要解决布局能力、交互响应、页面重绘和等待体验。模型推理、复杂 SQL 和 Python 生成的执行耗时仍由后端决定，不能用前端迁移承诺所有问题的总响应时间都会大幅下降。

## 3. 技术选型与取舍

以下为建议版本线；确认后在脚手架阶段核对兼容矩阵，锁定具体版本并提交 `package-lock.json`，不在构建时漂移使用 `latest`。

| 领域 | 建议选型 | 本项目中的职责 |
| --- | --- | --- |
| 应用基础 | React 19.x + TypeScript 严格模式 | 组件化复杂工作台，明确请求、响应与任务事件类型 |
| 构建 | Vite 8.x，npm | 开发热更新、按路由分包、构建静态产物；不增加 Node 业务服务器 |
| 路由 | React Router 8.x | 会话与报告深链接、浏览器前进后退、页面级懒加载 |
| 服务端状态 | TanStack Query 5.x | 会话、文件、任务、产物的缓存、去重、失效和错误恢复 |
| 客户端状态 | Zustand 5.x + 局部 React state | 按会话隔离草稿、下次数据选择、侧栏、预览与主题状态 |
| 基础组件 | Ant Design 6.x | Tree、Table、Drawer、Modal、Tabs、表单、进度与反馈 |
| 视觉系统 | Ant Design Token + CSS Modules + CSS 变量 | 自定义工作台、对话和报告附件外观，不照搬后台模板 |
| 正文 | react-markdown + remark-gfm | 渲染安全 Markdown；默认不执行原始 HTML |
| HTTP / 实时 | fetch + XMLHttpRequest 上传 + 原生 EventSource | 普通 API、真实上传进度、现有 SSE 协议；统一错误适配 |
| 大列表 | TanStack Virtual，按需求启用 | 长会话和事件列表的窗口化渲染，避免首版过早复杂化 |
| 接口类型 | openapi-typescript + 后端响应 DTO | API 类型生成与契约差异检查 |
| 验证 | Vitest、Testing Library、Playwright、axe-core | 状态与交互测试、真实浏览器流程、响应式及可访问性 |

选择 Ant Design 是因为本项目有文件树、数据库字段表、日志筛选、抽屉和大量状态交互。对话、报告附件和三栏容器仍自行组合；统一修改组件 Token，避免默认控件与定制区域视觉割裂。首版不叠加另一套大型 UI 框架或动画系统。

这是内部分析工作台，主要依赖已有 FastAPI，不以 SEO 或服务端页面渲染为目标，因此采用独立 React SPA。若以后建设公开内容站点或复杂服务端渲染，再单独评估框架层变化。[React 的自建应用指南](https://react.dev/learn/build-a-react-app-from-scratch)列出了 Vite、路由和数据获取工具的组合思路；[Ant Design 主题文档](https://ant.design/docs/react/customize-theme/)支持以设计 Token 定制控件。

## 4. 页面设计方向与布局示意

**产品定位：专业的数据分析工作台。** 核心是提问、理解结果、检查来源、继续修改报告，而非展示通用 SaaS 营销页面或无关 KPI 卡片。

既有设计要求作为视觉基线：中性浅灰页面、白色内容面、深色正文与克制的品牌蓝；普通组件圆角 6–10px。视觉丰富度来自合理的信息密度、表格、版本关系、可操作附件和明确状态，不依赖光晕、渐变或卡片层层嵌套。

| Token | 建议值 | 使用范围 |
| --- | --- | --- |
| `--bg-page` | `#F7F8FA` | 页面背景 |
| `--bg-surface` | `#FFFFFF` | 主对话、表格和抽屉 |
| `--text-primary` | `#26364B` | 正文与主要标题 |
| `--text-secondary` | `#64748B` | 说明、时间与技术指标 |
| `--brand-primary` | `#3D5BC7` | 主操作、选中状态与焦点 |
| `--border-default` | `#E2E8F0` | 分隔线与控件边界 |
| 字号与间距 | 正文 14–16px，4px 基础间距单位 | 中文阅读优先，数字使用等宽数字特性；标题不过度放大 |

界面设计会继续参考 frontend-design、UI/UX Pro Max 和现有产品规范。本次技能检索中的 Analytics Dashboard 建议适合数据密度与下钻；其中营销页、销售 CTA、AI 紫色默认建议不适合本项目，未采用。中文界面使用系统中英文字体栈，首版不依赖远程字体。

### 滚动与响应式规则

- 桌面使用 CSS Grid，关键子容器设置 `min-width: 0`、`min-height: 0`；应用壳使用动态视口高度，中间消息列表与右侧检查面板各自滚动，输入区留在底部。
- 页面不同时出现“整个窗口”和“主聊天框”两条无意义纵向滚动条。报告 iframe、数据表是有明确边界的独立阅读区域。
- 1280px 及以上优先三栏；1024–1279px 收起右栏；768–1023px 使用侧栏抽屉；更窄屏幕使用单列。最终以内容最小宽度和实际测试修正断点。
- 新消息仅在用户已经接近底部时跟随滚动；阅读旧消息时显示“有新内容”入口。展开报告和历史记录时保留阅读锚点，不突然跳到底部。
- 桌面业务控件可保持紧凑；移动端主要点击区域至少 44px，并提供键盘焦点、抽屉焦点回收和减少动态效果设置。

## 5. 页面与路由规划

| 页面 | 路由建议 | 主要内容与操作 |
| --- | --- | --- |
| 工作台入口 | `/` | 恢复最近会话或创建新会话；无数据时给清晰入口 |
| 数据对话 | `/sessions/:sessionId/chat` | 消息、输入区、当前任务、来源、报告附件 |
| 数据与知识库 | `/sessions/:sessionId/data` | KB 目录树、上传队列、文件画像、表字段与受限预览 |
| 文件与报告 | `/sessions/:sessionId/reports` | 按任务和版本组织报告、中间产物、下载与来源 |
| 报告阅读 | `/sessions/:sessionId/reports/:artifactId` | 大尺寸安全预览、版本切换、下载、基于此版修改 |
| 提问日志 | `/sessions/:sessionId/activity` | 问题、分派、状态、响应时间、Token 与增量运行事件 |
| Agent 记忆 | `/sessions/:sessionId/memory` | 两位专家独立记忆、状态筛选和已支持的删除操作 |

任务选中、报告预览和日志筛选可以写入 URL 查询参数。输入草稿与临时文件对象不写入 URL。浏览器刷新或复制链接后，从服务端恢复当前会话，而非依赖旧组件内存。

首版不增加未获业务依据的“全局经营大屏”，不在普通问题回答中主动加入无关统计。

## 6. 现有功能逐项迁移

| 现有能力 | React 中的实现方式 | 必须保留的规则 |
| --- | --- | --- |
| 新建、切换、删除会话 | 会话侧栏、搜索、删除确认、路由状态 | 切换不取消后端任务；删除后不能被旧订阅复活 |
| CSV / Excel / HTML 上传 | 拖拽区、文件队列、真实进度、画像状态 | 1 GiB 限额由后端最终校验；上传完成不等于分析完成 |
| KB 文件夹选择 | 按已有 `relative_path` 构建可搜索目录树 | 保留多选、父子勾选状态和文件 ID；上传文件单独分组 |
| PostgreSQL 来源与表 | 来源选择器、表/字段树、预览抽屉 | 显式清空不能自动恢复；受限身份不被旧快照扩大 |
| 数据问答 | Markdown 回答、明确任务反馈 | 默认只呈现直接结论，不把内部结果整表塞入消息 |
| 生成报告 | 对应助手回复下的报告附件 | 文件真正交付后才标记可预览/下载 |
| 修改报告 | 版本卡、指定基础版本、修改输入模式 | 新版与原版各自保留，未改内容和来源继承 |
| 运行日志 | 按需抽屉/面板、增量加载 | 显示实际角色、工具、原因与 `request_id`，不展示模型内部思考 |
| 耗时 / Token | 次级详情与日志表 | 保留 unknown / partial，思考与缓存 Token 不重复累计 |
| 取消 / 重试 / 补充信息 | 明确操作按钮和状态反馈 | 网络重连不触发重试；补充信息沿用原任务关联 |
| 记忆管理 | 专家分栏、列表和删除确认 | 不混用专家记忆，不暴露本地文件或秘密 |

## 7. API 对接与最小后端增补

现有 API 前缀继续为 `/api/v1`。新前端以 HTTP 合同为边界，不能读取 `state/` 或直接执行 Agent。

| 功能 | 已有接口 | 迁移处理 |
| --- | --- | --- |
| 服务状态 | `GET /health` | 读取 Worker、流式开关、模型配置状态和现有容量字段 |
| 会话 | `GET/POST /sessions`，`GET/DELETE /sessions/{sid}` | 复用已有消息、提问日志和 `report_versions` |
| 文件 | `GET/POST /sessions/{sid}/files`，`GET /kb/files`，`POST /kb/refresh` | 保留 multipart 字段 `files`、画像和维护任务反馈 |
| 发起问题 | `POST /sessions/{sid}/messages` | 保留 `Idempotency-Key` 及 202 返回的 `task_id` |
| 任务与进度 | `GET /tasks/{tid}`，`GET /tasks/{tid}/events?after=`，`GET /tasks/{tid}/stream` | 接入现有状态、审计游标和 SSE 游标；两类游标不混用 |
| 操作任务 | `POST /tasks/{tid}/cancel`、`POST /tasks/{tid}/retry` | 仅用户显式操作；重试请求也固定幂等键 |
| 产物 | `GET /tasks/{tid}/artifacts`、`GET /artifacts/{aid}/download` | 继续遵守交付状态、产物类型、来源和哈希校验 |
| 数据库 | `GET /database/sources`、`GET /database/sources/{id}/catalog`、`POST /sessions/{sid}/database/preview` | 复用受控表预览，不新增浏览器任意 SQL 入口 |
| 记忆 | `GET /memories/{agent}`、`DELETE /memories/{agent}/{id}` | 保持现有两位专家的边界 |

### 本次建议的兼容增补

1. **补齐响应 DTO。** 为会话、文件、任务、产物、Token 及事件补充响应模型，再生成 TypeScript 类型；合同回归验证字段、空值和额外兼容字段不丢失。SSE 的命名事件合同另设类型与运行时白名单。
2. **增加指定基础报告字段。** `MessageRequest` 增加可选 `base_report_id`。点击“基于此版本修改”时传入，服务端校验同会话、成功交付、报告种类、当前来源授权，并沿用原有版本/hash 锁定。现有请求省略此字段时继续保持原行为；不复用用于澄清的 `reply_to_task_id` 冒充版本选择。
3. **增加安全内联预览。** 新增 `GET /artifacts/{aid}/preview`，仅允许已交付且通过已有校验的 HTML 报告。与下载接口共用文件解析和授权逻辑，返回 `inline` 与正确 CSP；不把上传 HTML 或任意本地文件当作可信报告。
4. **增加前端静态文件与受限 SPA 回退。** 只服务 `frontend/dist`，API、`/docs` 和缺失静态资源不回退为 React 首页。

**按性能测量决定的后续增补：** 长会话可增加分页消息、轻量会话摘要和独立日志列表接口。首版优先限制现有重型会话详情的请求频率。现有状态保存在 JSON 中，仅对响应分页并不会消除底层全文件读取成本；大规模存储重构另行评估。

## 8. 前端状态与数据一致性

| 状态 | 唯一真值 | 前端策略 |
| --- | --- | --- |
| 消息、任务、报告、画像、记忆 | FastAPI 已保存的结果 | TanStack Query 按会话/任务分键缓存；终态刷新对应键 |
| 草稿、面板、下次提问选择 | 当前浏览器交互 | Zustand 按会话隔离；不把完整报告和消息复制成另一套业务存储 |
| 任务已使用的来源 | `task.spec` | 只读展示，不随下一题的数据选择变化 |
| 下一题的数据 | 草稿选择状态 | 提交时冻结为新的请求快照，并明确显示文件数与来源数 |
| 指定修改的报告 | `base_report_id` + 服务端锁定结果 | UI 显示版本；服务端负责校验、保持原版与冲突处理 |

特别保留三个语义：**尚未选择 / 明确选择 / 主动清空**。数据库字段不操作时允许省略，主动清空时必须发送空数组或空表列表，不能用默认序列化把“未操作”误变成清空。`analysis_ids` 也只在确有显式选择时发送，不能为省事自动补空值。

切换会话时中止旧 HTTP 读取和旧 SSE 订阅，响应提交前再次比对会话/任务 ID；它们不应更新新会话。浏览器刷新只恢复任务和消息，不能再次提交相同问题。删除会话要清理对应缓存、草稿和订阅，并处理服务端 404。

## 9. SSE、任务流与等待体验

```timeline
[
  {"time":"提交","title":"冻结本轮输入","text":"由点击事件发送一次 POST，固定幂等键；收到 202 后以 task_id 跟踪。"},
  {"time":"订阅","title":"读取已有任务快照并订阅 SSE","text":"只连接已有任务；关闭、刷新或重连页面不重新启动分析。"},
  {"time":"处理中","title":"显示分派与已验证内容","text":"进度描述使用后端事件，正文仅接收 verified=true 的结果片段。"},
  {"time":"结束","title":"核对终态并补齐附件","text":"读取规范任务结果，刷新对应会话与产物，关闭订阅和轮询。"}
]
```

订阅现有命名事件：`status`、`progress`、`verified_answer_segment`、`artifact_ready`、`snapshot`、`final`、`stream_unavailable`。不能只设置 `onmessage` 就假定会收到命名事件。每个正在展示的任务只维护一个订阅实例，由对话区和任务面板共同读取。

- 使用 `seq` 去重并续读；显式重连携带 `after`，保留原生 `Last-Event-ID` 机制。轮转缺口收到 `snapshot` 时替换检查点，再处理后续片段，避免重复拼接。
- 仅接受匹配 `task_id` 的事件；卸载时清理连接、计时器和回调。React 开发 StrictMode 的重复 effect 不得造成双 POST 或泄漏订阅。
- SSE 正常时，任务指标低频补充读取；日志只在展开时按 `events.after` 增量获取。异常时对当前任务采用约 2 秒轮询并退避，不高频重读整个会话。
- 订阅断线显示“连接恢复中”，不能显示“任务失败”。`stream_disabled` 时直接轮询。真正失败以持久化任务为准。
- `waiting_user` 显示“需要补充信息”，通过原有 `reply_to_task_id` 发起关联回答；不能标成报告已完成。
- 取消按钮先显示“正在请求取消”，等待后端终态；模型已完成与取消到达的竞态以服务端结果为准。
- 耗时与 Token 保留后端口径。界面可以显示经过时间，但不使用虚构百分比或假装模型内部思考已实时输出。

[MDN SSE 文档](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)说明命名事件、连接关闭和事件 ID；这里的具体状态、快照与校验规则来自项目现有协议。

## 10. 上传、知识库和数据库交互

### 1 GiB 文件上传

浏览器直接使用 `File` 与 `FormData`，不先把整个文件读取成 Base64 或 `ArrayBuffer`。XHR 提供真实传输进度，并使用后端返回值区分“传输完成”“等待画像”“可用于分析”。取消上传仅中止该上传请求；任务取消是另一项操作。

服务端的单文件、批次、所选输入总量和文件数量限制仍是最终约束。首版保留现有整文件上传合同，不承诺断点续传；上传失败由用户明确选择重试。若以后增加反向代理，须给 multipart 开销留空间，代理不能把现有 1 GiB 能力降成几十 MB。

### 文件树与预览

复用已存在的相对路径字段建立 KB 树；支持文件名筛选、父子选择和清晰的上传文件分组。文件 ID 是请求依据，路径仅作展示，不能把用户桌面绝对路径传给 Agent。首版不伪装支持服务端尚无合同的“任意文件夹上传/重命名”。

表字段、完整行数和质量说明来自已保存画像；大文件预览使用后端有界结果，不在浏览器解析整个 1 GiB 文件。画像失败显示原因和重新选择入口，不把文件数量与可分析数量混为一谈。

### PostgreSQL

来源名称、表、列、只读范围和受限身份说明来自后端。预览只在用户点击时发起受控请求；不因切页重复查询业务数据。表列表为空表示不读取任何表，历史报告的可见性也不能突破当前账号的数据库权限。

## 11. 报告附件、版本修订与 SVG

每份报告留在生成它的助手回复下，按 `session_id + task_id + artifact_id` 稳定绑定。正文相同的两条回复也必须区分任务；不能用回答字符串去重而隐藏新版报告。历史无明确任务归属的文件不猜测所属轮次，提供独立报告列表入口。

| 操作 | 用户看到的行为 | 后端约束 |
| --- | --- | --- |
| 在对话中预览 | 在该回复下按需展开单份报告 | 校验为已交付 HTML 报告，按版本 ID 读取 |
| 打开报告 | 大尺寸阅读页或抽屉，支持深链接 | 不改变报告版本，不发起 Agent 调用 |
| 下载 | 直接下载对应 HTML / Excel | 保留现有下载状态和哈希校验 |
| 基于此版本修改 | 输入区明确显示基础版本，可退出修改模式 | 新字段锁定基础版本；另存新版，原版仍可打开 |
| 修改图表 | 更换真实图、范围、文案或颜色 | 复用有效结果；缺图时分析 Agent 生成真实 SVG，不能把 CSV 表 ID 当图表 ID |

建议以安全预览接口作为 iframe 来源，使用 `sandbox="allow-scripts allow-downloads"` 并继承后端 CSP，不加入 `allow-same-origin` 或顶层导航权限。可信图表的缩放、系列选择、重置和 SVG 导出需要在受限 iframe 中逐项验证；不能简单关闭脚本导致交互消失。上传的任意 HTML 不通过这个可信预览入口执行。

Excel 提供下载及已有元信息，不承诺浏览器完整还原工作簿。长 HTML 不自动插入全部历史消息，展开时再加载；普通 Markdown 回答不通过 `dangerouslySetInnerHTML` 执行。

报告仍默认结论优先、不含“指标汇总”和原始结果整表。局部修订流程沿用原有基础版本、目标、补分析与新文件发布机制；前端不自行替换 HTML 文本冒充完成修订。

## 12. 性能与反馈目标

以下是开发验收预算，不是当前系统的实测成绩；须在实施时记录浏览器、数据规模、网络和测试方式。

| 指标 | 首版目标 | 验证方法 |
| --- | --- | --- |
| 提交/切换的即时反馈 | 本机交互约 100ms 内给出按钮或骨架状态，不等待 LLM | Playwright 记录交互时间与请求开始时间 |
| 常用页面可交互 | 本地正式构建冷加载目标 2 秒量级，缓存切换更快 | 1440px 桌面与真实浏览器性能记录；超预算定位依赖包和请求 |
| 首屏资源 | 首屏 JS gzip 目标不超过约 500KB；大编辑器等按需加载 | 构建体积报告，依赖分析与路由分包 |
| 长会话 | 100 条以上消息启用窗口化或分段加载验证，1000 条样本仍能平稳输入 | 合成记录、DOM 数量、滚动和输入检查 |
| 请求数量 | 不随历史任务数逐个轮询；仅当前任务与展开日志有活动读取 | 网络面板检查，无重复提交和轮询风暴 |
| 报告 | 非展开时不下载全部 HTML；下载不将 1 GiB 原文件缓存到 JS 内存 | 网络与内存观察，关闭预览释放资源 |
| 模型耗时与 Token | 与原后端分开统计，前端读取不触发新模型调用 | 对比同一任务后端事件和前端网络请求 |

使用 [TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview)管理远程状态，组件仅订阅需要的切片；高频进度更新不重绘文件树和所有历史消息。读请求有有界退避，写请求默认不自动重试。主题、抽屉和页面切换使用短小、由操作触发的过渡，避免大面积连续动画。


## 16. 验收清单

### 核心业务

- 新建、切换、删除会话与刷新恢复；相同文案的不同任务不混淆。
- 文件单指标问答只呈现所问结论；SQL 分析保持真实来源、只读和 RLS。
- CSV / Excel / HTML 上传和画像可用；超过容量有明确反馈，不以客户端检查替代服务端限制。
- KB 文件夹可展开、搜索、多选；文件数量、来源数量与实际发送参数一致。
- 生成 HTML / Excel 报告后附着到对应回复；新提问不移走旧附件。
- 原版与多次修订版均能预览下载；选中旧版修改能准确锁定基础版本。
- 修改任意章节、翻译、图表和 Top 范围时，只改目标部分并保留原报告。
- 报告 SVG 的缩放、重置、系列选择和导出在受限 iframe 中仍可使用；没有中文缺字。

### 状态、异常与成本

- SSE 断线、重复事件、日志轮转快照、后端重启和前端刷新都有恢复路径，不增加模型任务。
- `queued/running/succeeded/failed/waiting_user/cancelled/interrupted` 都有对应文案和可执行操作。
- 执行失败展示具体工具和脱敏原因；任务终态、报告可下载状态与数据来源不矛盾。
- 模型未返回用量显示未知，部分返回显示部分统计，不能补零或重复累计。
- 上传取消与任务取消分开；网络失败后的重试与用户再次提交不会产生隐蔽双 POST。

### 界面与工程

- 在 390、768、1024、1280、1440 和 1920px 宽度检查布局；页面无横向溢出，长表格仅在自身区域滚动。
- 右侧面板展开全部模块后仍能滚动到“运行记录”和“下次提问的数据”。
- 中文输入法 Enter 不误发；支持 Shift+Enter 换行和明确快捷键；软键盘不遮挡输入与发送。
- 键盘能完成选数据、提问、打开/关闭预览和取消对话框；焦点可见且不会丢失。
- API 合同、关键状态、组件交互和真实浏览器 E2E 通过；React 控制台无错误，无反复订阅泄漏。
- `npm ci / typecheck / test / build` 可复现；FastAPI 业务与权限回归继续通过。浏览器测试优先合成数据，真实模型验收限定用例并记录调用成本。
- 正式模式不启动 Streamlit；旧 API 路径可用，React 深链接可刷新，未知 API 和资源正确返回 404。
